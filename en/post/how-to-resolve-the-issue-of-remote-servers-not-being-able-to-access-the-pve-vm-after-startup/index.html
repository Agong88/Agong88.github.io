How to resolve the issue of remote servers not being able to access the PVE VM after startup?

Aug 29, 2026
2 minute read
中文

Okay, I think this is a bit clickbait, but if you’re like me and can’t remotely access your PVE VM after booting up, you might want to check out this article.

Background

The gist of the story is that I recently got my hands on a PVE machine. It has pretty good performance, and with memory prices skyrocketing, it still has 4TB + 128GB of storage available, so of course I want to make the most of it!

However, the owner of the computer is using a high-end UDM Pro Max to set up a VLAN, running on a certain network segment.

Problem

Whenever my VM is connected to the internet, I can’t access the remote server. It’s not just the VM, but the entire PVE instance.

Solution

After discovering the problem, I considered the following possible causes:

  1. The VM’s DHCP server is hogging the PVE’s IP address, preventing remote access.

  2. I made a mistake in one of my settings, but after checking for a long time, I found it was correct.

Solution to Cause 1

I enabled NAT so that all VM traffic is forwarded through the PVE’s IP address, as follows:

auto vmbr1
iface vmbr1 inet static
        address 192.168.100.1/24
        bridge-ports none
        bridge-stp off
        bridge-fd 0
        post-up echo 1 > /proc/sys/net/ipv4/ip_forward
        post-up iptables -t nat -A POSTROUTING -s '192.168.100.0/24' -o vmbr0 -j MASQUERADE
        post-down iptables -t nat -D POSTROUTING -s '192.168.100.0/24' -o vmbr0 -j MASQUERADE

I initially thought this was good enough, but for some reason, the VM network speed only reached a maximum of 20Mbps. Considering I’d have to manually configure the IP address for each machine and still only get 20Mbps, I figured there must be a better solution. So I continued researching.

The Real Problem at the End

After spending over half a month searching for information and similar problems on PVE and Google without success, I started to wonder if there was a problem with the higher-level UDM Pro Max settings. So I asked for a UniFi OS account to check.

What I found was shocking!

Why didn’t they mention setting the VLAN tag to Allow? I simply turned that setting off, and that solved the problem perfectly.
